# Agent Cookbook

Actionable patterns discovered during development, organized by domain. Entries marked `[promoted]` live in Tier 1 (`.claude/rules/`) -- kept here as one-liners for traceability.

## Promoted to Tier 1 (traceability index)

These entries are fully documented in `.claude/rules/architecture.md` or `.claude/rules/workflow.md`. One-line references only.

**Git / Rebase**: verify branch identity before `git reset --soft`; `git stash` removes uncommitted edits; module split conflicts take refactored facade; two-level rebase loop (commits x attempts); `_restore_stash()` on all early returns. See `workflow.md`, `architecture.md`.
**Git / Hooks**: `core.hooksPath` doesn't survive `git clone`; three layers auto-configure it. See `architecture.md`. Pre-push hook checks LOCAL branch name -- `git push origin local:remote` does NOT bypass branch-naming invariant; rename the local branch first (`git branch -m`). Worktrees get auto-named `worktree-*`; always rename before pushing.
**Testing**: dashboard service tests must isolate project dir via `monkeypatch.setattr`.
**Documentation**: doc counts drift after refactors; stale references persist after renames.
**Dashboard**: polling must clear stale UI on negative path; polling innerHTML refresh kills open dropdowns (reset interactive state flags in all grid-replacing functions); auto-handoff must clear file before spawning; SOVA review state lives in DB not GitHub; pipeline variant detection gates on `current_step`; `start_agent()` lifecycle hooks are role/mode-aware; DB-only status updates must also kill the process; `_finalize_task_run` guards against already-terminal runs; queue Phase badges come from issue milestones not Projects V2 fields (see `docs/issue-organization.md`); WebSocket incremental updates must cover all display fields or add separate refresh; handle sentinel step values explicitly in rendering; pipeline roles validated at exit: `current_step="agent"` + 0 steps = bypass, downgrade to "failed".
**Rebase conflict resolution**: when taking main's code block to resolve a conflict, also check main's import section -- new symbols in the block (e.g., `is_available`) may require import additions that fall outside the conflict markers. Always run `make lint` immediately after resolving conflicts and before `git rebase --continue`. PR #424.
**Workflow**: state-adopting steps replicate all side effects; CI fix loops for cross-boundary recovery; guard no-op pushes in LLM fix loops; seed cross-agent data before clearing handoff; headless agents told not to ask questions; headless prompts frame CLI commands as bash blocks; per-issue handoff files for parallel isolation; `recover_stale_runs` checks external state for merge-role runs; address-review independent worktree discovery (both `start_agent` and `start_command` resolve worktrees via shared `_resolve_branch_name()` helper); address-review finding loading uses four fallback sources (handoff file, DB, issue DB, GitHub PR reviews); monitor_ci zombie recovery uses four layers (heartbeat, step timeout, watchdog kill, periodic recovery); `/address-pr` wrong-directory: check `git branch --show-current` == headRefName before any edits; STOP if no matching worktree -- never `git checkout <BRANCH>` in the main repo.
**Config**: new config sections need triple registration; removing a Pydantic field requires removing it from `sova.toml`, `sova.toml.default`, and settings_meta too (Pydantic rejects extra inputs); place shared adapter helpers (e.g., `jira_issue_key()`) on the config model, not as private functions in step files.
**External tools**: `all([]) == True` trap in polling loops; `list[-0:]` returns full list (3 occurrences); exception hierarchy in except tuples; only resolve threads after confirmed fixes; CodeRabbit CHANGES_REQUESTED persists across force-pushes; reply before resolving; `/address-pr` fix-before-reply; dismissing review and resolving threads are separate ops; bot threads: resolve Fixed+Acknowledged; human threads: Fixed only; always dismiss bot CHANGES_REQUESTED reviews via `PUT /reviews/{id}/dismissals` after addressing findings.
**aiosqlite/SQLAlchemy async sessions on Python 3.12**: `session.close()` and `session.rollback()` hang (10+ seconds) after a failed query on Python 3.12 + aiosqlite because the thread running the SQLite rollback gets stuck. Fix: use raw `aiosqlite.connect()` directly instead of SQLAlchemy `AsyncSession` for read-only fleet queries -- aiosqlite connection cleanup is clean after errors. Do NOT use `isolation_level=None` (connect_arg) or `NullPool` as workarounds -- they don't prevent the hang. [PR #443]
**GitHub API**: `gh pr comment` posts conversation comments not inline; GitHub rejects REQUEST_CHANGES/APPROVE on own PRs; `gh auth switch` does not persist across subprocesses; `GH_TOKEN` overrides `gh auth switch`; `pull_request_target` reads workflow from base branch (tamper-proof for fork gating); `_parse_issue()` and `get_state()` both infer task state from GitHub data -- keep them in sync: `get_state()` checks `data.get("state") == "CLOSED"` before label inference; `_parse_issue()` must do the same or closed issues become TRIAGED in the dependency graph and trigger infinite researcher re-spawns. PR #471.
**Supervisor**: repeated-failure circuit breaker pattern -- use `SELECT count(*) WHERE id > (SELECT coalesce(max(id),0) WHERE status='done')` to count failures since the last success; this correctly handles re-triaged issues without permanent blocking. Gate fires only for SPAWN_RESEARCHER (researchers have no other re-spawn protection). `_collect_gate_blockers()` conditionally appends per-action gates to the async gather list. PR #471.
**Dashboard**: `_project_page()` in multi-project mode passes only `{page, project_slug, project_name, prefix, **extra}` -- it does NOT load per-project config. Routes that need per-project context (e.g., `github_repo` for the supervisor template) must load config themselves and pass it via `**extra`. Use the module-level `_try_load_config(proj_path)` helper (already in `app.py`) which handles exceptions internally; do NOT add a bare `except Exception` in the route handler (triggers BLE001). Pattern: `proj_path = get_project_path(slug); cfg = _try_load_config(proj_path); github_repo = cfg.github_repo or "" if cfg else ""`. Always annotate `_try_load_config` return type as `ProjectConfig | None` (not `object | None`) so callers benefit from type checking on `.github_repo` and similar attributes; add `ProjectConfig` to the `TYPE_CHECKING` block since it's only needed for annotations. Requires `from __future__ import annotations` at the module top (makes all annotations lazy strings, avoiding `NameError` at runtime); alternatively use a string literal `-> "ProjectConfig | None"`. PR #471, #473.
**CI / SonarCloud transient**: two recognizable transient failure signatures: (1) `UnsatisfiedDependencyException: Unable to create analysis` (Spring DI init error in the scanner); (2) `HttpException: Error 500/504 on https://sonarcloud.io/batch/project.protobuf ... "An unexpected error occurred. Please try again later."` (API endpoint outage). Both are server-side and unrelated to code. All other CI checks still count; treat the PR as green if Python Tests, Static Checks, Lint, and Invariants pass. Re-run the SonarCloud job up to 2x before escalating. PR #405.
**Other promoted**: config-driven provider selection wired at startup; SonarCloud `pull_request_target` security model; SonarCloud scanner needs explicit PR args; SonarCloud quality gate needs `statuses: write`; distributable commands need dual install; dispatch shell mocks by command args; file-based handoff persisted to DB at finalization; `if not handoff:` vs `if handoff is None:` for JSON columns; CI fix loop returns on poll timeout without new failure data; check external state before marking multi-phase runs failed; config nesting at most two levels deep; mirror changes across SOVA/distributable command pairs.

## Testing

- **Integration tests needed for complex SQL correlated subqueries; unit mocks only verify behavior, not SQL correctness** -- a unit test that mocks the DB count returned by a query (e.g., `_check_repeated_failures_gate`) verifies control flow but never executes the SQL. A correlated subquery like `SELECT count(*) WHERE id > (SELECT coalesce(max(id),0) WHERE status='done')` can have off-by-one boundary bugs or wrong column references that only appear with real rows. Add an integration test class with `sqlite+aiosqlite:///:memory:` and seeded `TaskRun` records covering: (1) failures before a success excluded, (2) failures since last success at threshold trigger block, (3) all failures count when no prior success. Use `yield` fixture teardown with `await engine.dispose()`. PR #473. [confirmed: 1]
- **Helper functions returning `object | None` should return concrete types when callers access specific attributes** -- `_try_load_config()` declared `object | None` but callers access `.github_repo`. This hides attribute errors from static checkers. Return the concrete `ProjectConfig | None` type. For circular-import safety, guard the import with `TYPE_CHECKING`: `if TYPE_CHECKING: from sova.config.models import ProjectConfig`. The module must have `from __future__ import annotations` (or use string annotation `-> "ProjectConfig | None"`) so the runtime doesn't evaluate the annotation eagerly and raise `NameError`. PR #473. [confirmed: 1]
- **Functions locally-imported in a helper (`from x import y as z` inside a function) must be patched at the import source, not at the module** -- `run_shell` imported as `from sova.utils.shell import run as run_shell` inside `_check_pr_branch_pushed()` creates a local name that `monkeypatch.setattr("sova.dashboard.services.agent_db.run_shell", ...)` cannot reach. Patch `sova.utils.shell.run` instead. PR #347. [confirmed: 1]
- **Add direct unit tests for functions that are mocked in higher-level tests, or SonarCloud will flag 0% coverage** -- if `_is_issue()` and `_check_pr_branch_pushed()` are always mocked in integration tests, SonarCloud sees 0% new coverage even though the feature is tested indirectly. Add `TestIsIssue` / `TestCheckPrBranchPushed` with direct calls to cover the actual implementation paths. Same pattern in PR #400: `_fetch_github_review_fallback` was always mocked in `TestFetchSovaVerdictsGithubFallback`; adding `TestFetchGithubReviewFallback` (4 direct tests) fixed the SonarCloud gate. PR #347, #400. [confirmed: 3]
- **except blocks in page routes need test coverage for the SonarCloud gate** -- `except Exception` handlers that swallow errors (e.g., config load fallback in `supervisor_page`) add uncovered lines to new code. SonarCloud's `new_coverage` threshold (80%) is sensitive to small line counts: 3 uncovered out of 14 new lines = 78.6%, failing the gate. Always add a test with `side_effect=RuntimeError(...)` that triggers the except path. PR #462. [confirmed: 1]
- **`git reset --soft` must target the branch base, not `origin/main`** -- if main has moved forward since the branch was cut, `git reset --soft origin/main` resets to a newer commit, leaving main's changes as unstaged modifications in the working tree. Find the parent of the first branch commit (`git log --format="%H" -1 <first_commit>^`) and reset to that SHA instead. PR #462. [confirmed: 1]
- **Heuristic regex searches must be scoped to the relevant section, not the full document** -- `_SOVA_VERDICT_LINE_RE.search(body)` in the heuristic fallback ran on the whole review body. A bold line starting with `**Approve...` in `## Findings` would match before the actual `## Verdict` entry. Fix: `verdict_section = body.split("## Verdict", 1)[-1]` before searching. General pattern: when scanning for a value that appears in a named section, split on the section header first. PR #400. [confirmed: 1]
- **Update hardcoded Alembic head revision in tests after adding a migration** -- `test_get_alembic_head_returns_current_head` asserts a specific revision string (e.g., `"020"`). After adding a new migration, update the assertion. File: `tests/test_db.py`. PR #354, #399. [confirmed: 2]
- **Type DB session parameters with `AsyncSession`, not `Any`** -- internal helpers that accept a SQLAlchemy session (e.g., `_count_nonterminal_for_issue`) must use `session: AsyncSession` not `session: Any`. `Any` triggers Ruff ANN401 and loses type-checker benefits. Import from `sqlalchemy.ext.asyncio`. Remove `from typing import Any` if no other `Any` usage remains. PR #354. [confirmed: 1]
- **Lazy imports inside functions must be patched at the source module, not the consumer** -- `from sova.adapters import create_adapter` inside `ensure_agent_labels()` creates a local binding at call time; `patch("sova.dashboard.services.setup_service.create_adapter")` fails. Patch `sova.adapters.create_adapter` (the source) instead. Same for `find_slug_for_path` imported inside `execute_decision()`: patch `sova.config.registry.find_slug_for_path`, not `sova.supervisor.progression.find_slug_for_path`. PR #358, #477. [confirmed: 2]
- **Base class no-op methods need a dedicated test; higher-level mocks replace the whole method** -- adapter tests that set `adapter.ensure_repo_labels = AsyncMock(return_value=[])` never exercise the base class code. Add a `TestTaskAdapterInterface` test that creates a minimal concrete subclass and calls the no-op directly. PR #358. [confirmed: 1]
- **Runtime/stress/chaos tests excluded from CI via pytest markers** -- `tests/runtime/` uses `@pytest.mark.runtime`, `@pytest.mark.stress`, `@pytest.mark.chaos`. `make test-py` adds `-m "not runtime and not stress and not chaos"` to keep CI fast. `make test-runtime` runs only heavy tests with 120s timeout. New process lifecycle tests go in `tests/runtime/`, not `tests/test_dashboard.py`. PR #341. [confirmed: 1]
- **Module-level cache requires `setup_method` in ALL test classes that call the cached function** -- adding a module-level `dict` cache to a service function makes every test class that calls that function share state. Adding `setup_method` only to the new test class leaves existing classes vulnerable to poisoning from cache hits left by previous tests. Add `setup_method: clear_cache()` to every class in the file that invokes the cached function, not just the new ones. PR #405. [confirmed: 1]
- **MagicMock `__truediv__` creates filesystem-illegal filenames when Path mock is evaluated** -- if a `Path` is mocked and code evaluates `path / ".claude" / "sova.db"` during a test run, the result is a `MagicMock` object whose `str()` is literally `<MagicMock name='mock.__truediv__().__truediv__()' id='...'>`. If that string gets passed to `db_path.parent.mkdir()` or `open()`, Python creates a file with that literal name. These files must be deleted before committing and are easy to miss with `git add`. Fix: mock at a higher level (patch `list_projects` to return real `tmp_path` entries) so `Path.__truediv__` is never invoked on a mock. PR #430. [confirmed: 1]
- **`MagicMock(name="foo")` sets the debug repr, NOT the `.name` attribute** -- `name=` is a reserved `MagicMock` constructor arg that controls the mock's display string (e.g., in tracebacks). To set the `.name` attribute, assign after construction: `mock = MagicMock(); mock.name = "foo"`. Tests that check `x in mock.name` or `mock.name == "foo"` silently pass for the wrong reason because `MagicMock.__contains__` defaults to `False` and attribute access returns a new mock. PR #418 CodeRabbit. [confirmed: 1]
- **`MagicMock().__truediv__()` leaks as literal filenames when evaluated against `Path.__truediv__`** -- if a test helper creates a real SQLite file at a `Path` that is actually a `MagicMock`, Python evaluates `mock_path / ".claude" / "sova.db"` and returns a `MagicMock` whose `str()` becomes `"<MagicMock name='mock.__truediv__().__truediv__()' id='...'>"`. Any code that does `open(str(path))` or `sqlite3.connect(str(path))` will create real files with those names. Gate test helpers that create real files with `assert isinstance(path, Path)` or pass `tmp_path / "subdir"` explicitly rather than a mocked path. PR #443. [confirmed: 1]
- **Mock-based gate tests cannot verify correlated SQL subqueries -- use a real DB** -- `TestRepeatedFailuresGate` mocked `scalar_one_or_none()` to return a count, so the correlated subquery (`WHERE id > (SELECT max(id) WHERE status='done')`) was never executed. CodeRabbit caught this: the test passed with incorrect SQL. Fix: add a DB-backed integration class with `sqlite+aiosqlite:///:memory:`, seed real `TaskRun` rows in failed/done/failed sequence, call the gate, assert only failures after the `done` row count. Pattern applies to any gate or service that uses a subquery for its filtering logic. PR #473. [confirmed: 1]

## Dashboard / Frontend

- **SOVA review gate must fall through to PR-only lookup when issue_number is None** -- `check_integration_gates` guarded with `if not issue_number: skip`. But `get_sova_review_verdict` already handles `issue_number=None, pr_number=N` for unlinked PRs. Guard should be `not issue_number and pr_data.get("number") is None`. When updating such guards, rename the test that asserts the old skip behavior and add a new test for the PR-only path. PR #477. [confirmed: 1]
- **Daemon lifecycle ops (start/stop) need dedicated POST endpoints; UI cannot rely on config flag alone** -- setting `supervisor.enabled=false` in config does not cancel the running asyncio task. Add `POST /supervisor/stop` that calls `daemon.stop()` and pops the daemon from the registry. The disable UI function should call the stop endpoint after saving config (swallow 404 if not running). Pattern: start endpoint + stop endpoint, both guarded by `_start_lock`. PR #477. [confirmed: 1]
- **`_confirmPoll` intervals must be cleared in all exit paths** -- any JS interval started in one function (e.g., `enableSupervisor`) must be cleared before starting a new one, in the disable path, and in `beforeunload`. Without this, navigating away leaves the interval running. Pattern: `if (_confirmPoll) { clearInterval(_confirmPoll); _confirmPoll = null; }` as first line in disable, and in `beforeunload` handler. PR #477. [confirmed: 1]
- **Ungrouped nodes in a tier-based graph must go to tier 0, not maxTier+1** -- placing ungrouped nodes at `maxTier+1` puts them to the right of all grouped nodes. If a grouped dependent (lower tier) depends on the ungrouped node (now higher tier), `tx - sx` is negative, the bezier handle clamps to a minimum, and the arrow draws backwards. Place ungrouped nodes at tier 0 (leftmost) to preserve the left-to-right invariant. PR #477. [confirmed: 1]
- **Sort tier functions must explicitly exclude transitional states before checking group membership** -- when using a set like `_PR_STAGE_STATES` to assign a sort tier, a broader set (e.g., one that includes `pr_draft`) can inadvertently promote transitional/internal states above items that need human attention. Always add explicit early returns for states that should not be promoted: `if (item.state === 'pr_draft') return 5;` before `if (_PR_STAGE_STATES.has(item.state)) return 2;`. The sort-tier function and the filter set may diverge from server-side ordering when a new state is added; verify both sides. PR #479. [confirmed: 1]
- **Agent re-run functions must pass `prNumber` through to the start call** -- `rerunAgent(issue, role, prNumber)` receiving `prNumber` from `data-pr` but ignoring it in the body means a re-run of a developer run that had an open PR skips `pr_number` in the API payload. Without it, the agent assesses fresh rather than entering the address-review pipeline. Always pass through: `_doStartAgent(issue, role === 'auto' ? null : role, false, prNumber || null)`. Server-side `_recover_last_pr_number()` provides a partial fallback but is not guaranteed. PR #479. [confirmed: 1]

- **Badges use `rounded-full`, buttons use `rounded`** -- visual distinction between read-only state indicators (pills) and clickable actions (rectangles). Badges: `px-2 py-0.5 rounded-full`. Buttons: `px-3 py-1 rounded`. Without this, users can't tell what's clickable. [confirmed: 1]
- **Range slider max must match Pydantic field constraint (le=N)** -- if slider HTML has `max="10"` but the backend Pydantic model accepts `le=20`, users can never reach the valid upper range via the UI. Always align front-end widget bounds (`min`, `max`) with backend validation bounds (`ge`, `le`). PR #298. [confirmed: 1]
- **Fixed-width columns for right-aligned badge/button groups** -- wrap PR badge, state badge, and action button in a fixed-width container (e.g., `style="width:340px"`) with internal fixed-width divs. Without this, variable text widths cause ragged vertical alignment across rows. [confirmed: 1]
- **Multi-action handoffs expand into a sub-row, not cramped inline** -- single-action handoffs (e.g., "Integrate PR") render on the main row. Multi-action handoffs (e.g., spec review with 4 buttons) expand into a second line below the title with summary text + buttons. [confirmed: 1]
- **Clickable card pattern: cursor-pointer + stopPropagation on nested buttons** -- add `cursor-pointer hover:opacity-80` on clickable element with `onclick`. All nested interactive elements must call `event.stopPropagation()`. File: `sova/dashboard/templates/agents.html`. [confirmed: 1]
- **Extract shared CAS patterns to avoid SonarCloud duplication gate** -- when multiple functions share validation + atomic CAS update logic (e.g., `resume_from_approval` and `reject_spec`), extract a shared helper parameterized by target status. Without this, the duplicated block triggers SonarCloud's 3% new code duplication threshold. PR #334. [confirmed: 1]
- **DB-level tests needed for functions mocked in router tests** -- router tests that mock service functions (e.g., `reject_spec`, `_find_awaiting_approval_run`) provide integration coverage for the router but leave the service function at 0% coverage. Add separate DB-level tests that seed TaskRun records and call the service directly. PR #334: coverage went from 35.8% to 95.6%. [confirmed: 1]
- **Update redirect chains when consolidating pages** -- when page A merges into B and old routes C,D redirected to A, update C,D to redirect to B. Also update sidebar nav, back-links, "View all" links, architecture.md page counts, and delete dead templates. [confirmed: 1]
- **Track notified IDs, not state transitions, for completion alerts** -- track seen `run_id`s to avoid missed/duplicate completion notifications. [confirmed: 1]
- **Disable async action buttons during operations** -- set `button.disabled = true` at function start, re-enable in `finally`. [confirmed: 1]
- **Wrap all API cost values with `parseFloat()` before `.toFixed()`** -- `Decimal` serializes as strings, `"0.000000".toFixed(2)` throws TypeError. Always `parseFloat(value || 0).toFixed(N)`. [confirmed: 1]
- **No nested `<a>` tags** -- use `issueOrPrLabel()` (`<span>`) inside `<a>` containers, `issueOrPrLink()` (`<a>` + stopPropagation) inside `<div onclick>`. [confirmed: 2]
- **Gate secondary badges when primary label shows same entity** -- suppress duplicate PR badge when PR is already in the issue label position. PR #408. [confirmed: 1]
- **marked.js v15 heading renderer uses token object** -- `heading({ tokens, depth })` not `heading(text, level)`. [confirmed: 1]
- **Key-based cache prevents re-render on every poll** -- store a key string from computed metrics; only rebuild DOM when the key changes. Pattern: `var key = values.join(','); if (key === _lastKey) return; _lastKey = key;`. Used in `renderPrSummary()` for PR metrics strip. [confirmed: 1]
- **Always add `type="button"` to `<button>` elements in dashboard templates** -- without an explicit type, browsers default to `type="submit"`. Harmless when standalone but breaks form submissions if buttons ever land inside a `<form>`. CodeRabbit (HTMLHint) flags this as a warning; adding `type="button"` silences it and prevents future regression. PR #480. [confirmed: 1]
- **Offset-aware UTC datetimes must normalize to Z-suffix before sending to JS** -- Problem: `datetime.isoformat()` on an offset-aware datetime (e.g., `datetime.now(timezone.utc)`) produces `"2026-07-26T08:01:13+00:00"`. JS that guards with only `!ts.endsWith('Z')` appends `Z`, producing unparseable `...+00:00Z`. Fix: in Python, emit `dt.isoformat().replace("+00:00", "Z")`. JS guard: use a regex to detect any timezone offset suffix: `const utcTs = ts && !/[+-]\d{2}:\d{2}$/.test(ts) && !ts.endsWith('Z') ? ts + 'Z' : ts`. Note: `!ts.includes('+')` alone is insufficient -- negative offsets like `-05:00` also need blocking; the regex handles both. File: `sova/supervisor/daemon.py:get_status()`. PR #480. [confirmed: 1]
- **Python naive UTC datetimes become wrong time in browser JS** -- `datetime.isoformat()` on a naive datetime (no tzinfo) produces `"2026-07-24T13:18:50"` (no suffix). JS `new Date("2026-07-24T13:18:50")` treats it as LOCAL time, not UTC; users in UTC+2 see times 2 hours behind. Fix: in JS, append `'Z'` when the suffix is absent: `const utcTs = ts && !ts.includes('+') && !ts.endsWith('Z') ? ts + 'Z' : ts`. All SQLAlchemy async sessions with SQLite return naive UTC datetimes. [confirmed: 1]
- **D3 force graphs scramble layout on every poll; diff-before-rerender prevents it** -- store a key string from the graph data (sorted node ids + states + edges); only call `renderGraph()` when the key changes. `_computeGraphKey(data)` on each `loadGraph()` call returns instantly; the full D3 simulation runs only on real state changes. Preserves node positions the user has dragged between polls. Pattern: `let _graphKey = null; if (_computeGraphKey(data) === _graphKey) return; _graphKey = newKey; renderGraph(data);` [confirmed: 1]
- **`esc()` (DOM-based HTML encoding) does not escape single quotes for attribute context** -- the standard `esc()` helper uses `element.textContent = str; return element.innerHTML` which encodes `<>&"` but NOT `'`. Using `esc(value)` inside `onclick="fn('${esc(val)}')"` is unsafe if `val` can contain `'`. Use `data-*` attributes + a static event delegation listener instead: `<button data-value="${esc(val)}" class="action-btn">...` and `container.addEventListener('click', e => { const b = e.target.closest('.action-btn'); if (b) fn(b.dataset.value); });`. PR #462. [confirmed: 1]
- **Static SVG layout outperforms force simulation for organized grouped graphs** -- when nodes should be visually grouped by category (e.g., milestone) with a clear dependency direction, a deterministic layout (compute column from avg topological tier, arrange nodes in rows within each group box) produces a stable, readable result without simulation. D3 is still used for `select()`, `append()`, and event binding; only the position computation is manual. Eliminates re-scrambling on every re-render. PR #462. [confirmed: 1]
- **Poll-cycle JS functions need independent try-catch** -- any function called on every poll cycle (e.g., `renderPrSummary()`) that contains loops, divisions, or external calls should wrap its body in `try { ... } catch (e) { console.error('...failed:', e); /* hide the element that depends on this data, e.g.: */ targetEl.classList.add('hidden'); }`. Without this, a single thrown error cascades and breaks all rendering until page reload. The outer polling function's catch block does not protect inner functions called synchronously. PR #349. [confirmed: 1]

Existing patterns: SSE = `feed.py` (FeedService pub-sub + StreamingResponse); WebSocket = `agents.py:296` (_ConnectionManager). [confirmed: 2]

## CI / GitHub Actions

- **`paths-ignore` does not block required status checks** -- when a workflow is skipped due to path filtering, GitHub marks associated checks as "Skipped" (not "Pending"), which satisfies required-check enforcement. Safe to use even when CI jobs are required in branch protection rulesets. Confirmed GitHub behavior since 2022. PR #472. [confirmed: 1]
- **Cross-workflow artifact sharing between `pull_request` and `pull_request_target` is unreliable** -- both events trigger concurrently on the same push; downloading a CI artifact inside SonarCloud nearly always fails because the CI workflow hasn't finished yet. `continue-on-error: true` works as a fallback but expect near-100% fallback rate. Eliminate the duplicate `pytest --cov` run by restructuring into a single shared workflow, not by artifact download. PR #472 research. [confirmed: 1]
- **SOVA CI doc-only ignore list: `docs/**`, `personas/**`, `knowledge/**`, `assets/**`, `guidelines/**`, `skills/**`, `templates/**`, `'*.md'` (root-level only, GitHub Actions does not recurse single-segment globs)** -- `commands/**` is intentionally NOT ignored: `lint-static` validates YAML frontmatter there. - **GitHub CI workflows silently skip when a PR has merge conflicts** -- `mergeStateStatus: "DIRTY"` prevents workflow triggers even when `paths-ignore` doesn't apply. - **SonarCloud outages block all PRs when it's a required status check** -- SonarCloud can fail with HTTP 500/504 server-side errors (`sonarcloud.io/batch/project.protobuf` or `api.sonarcloud.io/analysis/analyses`), which is not a code issue. - **`mergeStateStatus: UNSTABLE` is mergeable when only non-required checks fail** -- GitHub reports UNSTABLE (not BLOCKED) when optional status contexts like CodeRabbit fail but all required checks pass. The PR is still mergeable via `gh pr merge`. ## Common Mistakes (tracked by occurrence)

- **Git conflict markers in sova.toml crash the dashboard at startup with TOMLDecodeError** -- an unresolved merge or stash pop leaves `<<<<<<< Updated upstream` / `=======` / `>>>>>>> Stashed changes` markers in `sova.toml`. Python's `tomllib` raises `TOMLDecodeError: Invalid statement (at line 2, column 1)` before any config is loaded, crashing the dashboard lifespan. Diagnostic: when the dashboard fails to start with `TOMLDecodeError: Invalid statement`, open `sova.toml` and look for conflict markers. Fix: pick one value and delete the three marker lines.
- **`perf` is not a valid commit type, `git` is not a valid scope** -- invariant only accepts `feat, fix, refactor, test, docs, chore, ci`. Use `fix(core)` for perf improvements, `core`/`dashboard` for `sova/git/` changes. Applies to programmatically generated commits too (e.g., `_ensure_committed`, LLM fix prompts): always `type(scope): ...`, never scopeless `type: ...` (except `ci:`). (occurrences: 3) [confirmed: 3]
- **Commit scope must reflect the file's actual directory, not a semantically related area** -- changes only in `sova/dashboard/templates/` must use `feat(dashboard):`, not `feat(core):`. The invariant accepts any registered scope syntactically, so semantic mismatches silently pass but mislead `git log --grep` and code archaeology. Always match scope to the deepest applicable directory: `dashboard`, `core`, `roles`, `cli`, `adapters`, etc. (occurrences: 1)
- **`except X as exc:` + `log.warning(..., exc_info=True)` leaves `exc` unused** -- remove `as exc` or ruff F841 fires. (occurrences: 2) [confirmed: 1]
