## DB / Models

- **`TaskRun` uses `started_at`, not `created_at`** -- most ORM models (FailureRecord, CostRecord, Memory, etc.) use `created_at`, but `TaskRun` uses `started_at` and `ended_at`. Referencing `TaskRun.created_at` raises `AttributeError` which broad `except Exception` blocks silently swallow, producing "data unavailable" instead of real results. Always verify column names against the model definition when writing queries. PR #625, #629. [confirmed: 2]

- **Scope `TaskRun` queries by role when the function is role-specific** -- a query filtering `issue_number + status` without a `role` filter can match a TaskRun from the wrong role (e.g., developer instead of researcher). When the caller's intent is role-specific (e.g., "find the researcher's awaiting_approval run"), add `TaskRun.role == "researcher"` to the WHERE clause. Without it, a newer non-researcher run shadows the intended target. PR #663. [confirmed: 1]
- **Add `id.desc()` as a deterministic tie-breaker in "most recent" queries** -- `order_by(started_at.desc()).limit(1)` is non-deterministic when two rows share the same timestamp. Add `.order_by(TaskRun.started_at.desc(), TaskRun.id.desc())` so the highest auto-increment ID wins. Applies to any "find the latest X" pattern. PR #663. [confirmed: 1]

## Testing

- **Mock process objects must expose `_proc` for shutdown handlers** -- `_wait_and_finalize`'s CancelledError handler calls `agent.process._proc.terminate()` and `_proc.kill()` directly (not `process.stop()`) to avoid double-cancellation. `MockAgentProcess` in `sova/ipc/testing.py` needs a `_MockSubprocess` inner object with `terminate()`, `kill()`, `wait()` and `returncode`. Without it, shutdown tests fail with `AttributeError: 'MockAgentProcess' object has no attribute '_proc'`. Pattern: when production code bypasses the public API to access internal attributes for resilience, the mock must match. PR #620. [confirmed: 1]
- **Spawn mock functions must use `**kwargs` to absorb new parameters** -- `async def _capture_spawn(prompt, cwd, env=None)` breaks when `spawn()` gains new kwargs (e.g., `output_dir`, `run_label`). Use `async def _capture_spawn(prompt, cwd, **kwargs)` and mock `_update_task_run_output_path` alongside `_update_task_run_pid`. File: `tests/test_dashboard.py`. PR #500. [confirmed: 1]
- **Integration tests needed for complex SQL correlated subqueries; unit mocks only verify behavior, not SQL correctness** -- a unit test that mocks the DB count returned by a query (e.g., `_check_repeated_failures_gate`) verifies control flow but never executes the SQL. A correlated subquery like `SELECT count(*) WHERE id > (SELECT coalesce(max(id),0) WHERE status='done')` can have off-by-one boundary bugs or wrong column references that only appear with real rows. Add an integration test class with `sqlite+aiosqlite:///:memory:` and seeded `TaskRun` records covering: (1) failures before a success excluded, (2) failures since last success at threshold trigger block, (3) all failures count when no prior success. Use `yield` fixture teardown with `await engine.dispose()`. PR #473. [confirmed: 1]
- **Helper functions returning `object | None` should return concrete types when callers access specific attributes** -- `_try_load_config()` declared `object | None` but callers access `.github_repo`. This hides attribute errors from static checkers. Return the concrete `ProjectConfig | None` type. For circular-import safety, guard the import with `TYPE_CHECKING`: `if TYPE_CHECKING: from sova.config.models import ProjectConfig`. The module must have `from __future__ import annotations` (or use string annotation `-> "ProjectConfig | None"`) so the runtime doesn't evaluate the annotation eagerly and raise `NameError`. PR #473. [confirmed: 1]
- **Functions locally-imported in a helper (`from x import y as z` inside a function) must be patched at the import source, not at the module** -- `run_shell` imported as `from sova.utils.shell import run as run_shell` inside `_check_pr_branch_pushed()` creates a local name that `monkeypatch.setattr("sova.dashboard.services.agent_db.run_shell", ...)` cannot reach. Patch `sova.utils.shell.run` instead. PR #347. [confirmed: 1]
- **Add direct unit tests for functions that are mocked in higher-level tests, or SonarCloud will flag 0% coverage** -- if `_is_issue()` and `_check_pr_branch_pushed()` are always mocked in integration tests, SonarCloud sees 0% new coverage even though the feature is tested indirectly. Add `TestIsIssue` / `TestCheckPrBranchPushed` with direct calls to cover the actual implementation paths. Same pattern in PR #400: `_fetch_github_review_fallback` was always mocked in `TestFetchSovaVerdictsGithubFallback`; adding `TestFetchGithubReviewFallback` (4 direct tests) fixed the SonarCloud gate. PR #347, #400. [confirmed: 3]
- **except blocks in routes and services need test coverage for the SonarCloud gate**: `except (OSError, Exception)` handlers that swallow errors add uncovered lines to new code. SonarCloud's `new_coverage` threshold (80%) is sensitive to small line counts: 17 uncovered out of 60 new lines = 71.7%, failing the gate. Always add a test with `side_effect=OSError(...)` or `side_effect=RuntimeError(...)` that triggers each except path. For file I/O errors, use `patch.object(Path, "read_text", side_effect=OSError("disk error"))` and `patch.object(Path, "write_text", side_effect=OSError("read-only fs"))` to test read and write failures independently. PR #462, #817. [confirmed: 2]
- **`git reset --soft` must target the branch base, not `origin/main`** -- if main has moved forward since the branch was cut, `git reset --soft origin/main` resets to a newer commit, leaving main's changes as unstaged modifications in the working tree. Find the parent of the first branch commit (`git log --format="%H" -1 <first_commit>^`) and reset to that SHA instead. PR #462. [confirmed: 1] Related: worktrees can accumulate pre-existing uncommitted changes from prior agent sessions; `git reset --soft + git reset HEAD .` surfaces them alongside the commits' changes. Always run `git status` before starting a squash flow in an existing worktree. [PR #510]
- **Heuristic regex searches must be scoped to the relevant section, not the full document** -- `_SOVA_VERDICT_LINE_RE.search(body)` in the heuristic fallback ran on the whole review body. A bold line starting with `**Approve...` in `## Findings` would match before the actual `## Verdict` entry. Fix: `verdict_section = body.split("## Verdict", 1)[-1]` before searching. General pattern: when scanning for a value that appears in a named section, split on the section header first. PR #400. [confirmed: 1]
- **Use `monkeypatch.setenv` not `os.environ` mutation in test fixtures** -- `os.environ["KEY"] = value` persists across tests if not cleaned up, causing fixture pollution. `monkeypatch.setenv("KEY", value)` is automatically reverted at fixture teardown. Particularly important for `SOVA_DATABASE_URL` in DB-backed test fixtures. PR #653. [confirmed: 1]
- **Update hardcoded Alembic head revision in tests after adding a migration** -- `test_get_alembic_head_returns_current_head` asserts a specific revision string (e.g., `"020"`). After adding a new migration, update the assertion. File: `tests/test_db.py`. PR #354, #399. [confirmed: 2]
- **Type DB session parameters with `AsyncSession`, not `Any`** -- internal helpers that accept a SQLAlchemy session (e.g., `_count_nonterminal_for_issue`) must use `session: AsyncSession` not `session: Any`. `Any` triggers Ruff ANN401 and loses type-checker benefits. Import from `sqlalchemy.ext.asyncio`. Remove `from typing import Any` if no other `Any` usage remains. PR #354. [confirmed: 1]
- **Lazy imports inside functions must be patched at the source module, not the consumer** -- `from sova.adapters import create_adapter` inside `ensure_agent_labels()` creates a local binding at call time; `patch("sova.dashboard.services.setup_service.create_adapter")` fails. Patch `sova.adapters.create_adapter` (the source) instead. Same for `find_slug_for_path` imported inside `execute_decision()`: patch `sova.config.registry.find_slug_for_path`, not `sova.supervisor.progression.find_slug_for_path`. Also applies to `_load_consensus_config()` and `_create_providers()` in `sova/git/rebase.py` which import `load_config` and `LiteLLMProvider` locally. PR #358, #477, #716. [confirmed: 3]
- **Base class no-op methods need a dedicated test; higher-level mocks replace the whole method** -- adapter tests that set `adapter.ensure_repo_labels = AsyncMock(return_value=[])` never exercise the base class code. Add a `TestTaskAdapterInterface` test that creates a minimal concrete subclass and calls the no-op directly. PR #358. [confirmed: 1]
- **Runtime/stress/chaos tests excluded from CI via pytest markers** -- `tests/runtime/` uses `@pytest.mark.runtime`, `@pytest.mark.stress`, `@pytest.mark.chaos`. `make test-py` adds `-m "not runtime and not stress and not chaos"` to keep CI fast. `make test-runtime` runs only heavy tests with 120s timeout. New process lifecycle tests go in `tests/runtime/`, not `tests/test_dashboard.py`. PR #341. [confirmed: 1]
- **Module-level cache requires `setup_method` in ALL test classes that call the cached function** -- adding a module-level cache to a service function makes every test class that calls that function share state. Adding `setup_method` only to the new test class leaves existing classes vulnerable to poisoning from cache hits left by previous tests. Add `setup_method: clear_cache()` to every class in the file that invokes the cached function, not just the new ones. When changing a cache's type (e.g., `tuple | None` -> `dict`), grep ALL test files for the old reset pattern (`= None`) and update to the new one (`.clear()`); tests pass individually but ERROR in the full suite when one class corrupts the module-level variable for subsequent classes. PR #405, #595, #767. [confirmed: 4]
- **MagicMock `__truediv__` creates filesystem-illegal filenames when Path mock is evaluated** -- if a `Path` is mocked and code evaluates `path / ".claude" / "sova.db"` during a test run, the result is a `MagicMock` object whose `str()` is literally `<MagicMock name='mock.__truediv__().__truediv__()' id='...'>`. If that string gets passed to `db_path.parent.mkdir()` or `open()`, Python creates a file with that literal name. These files must be deleted before committing and are easy to miss with `git add`. Fix: mock at a higher level (patch `list_projects` to return real `tmp_path` entries) so `Path.__truediv__` is never invoked on a mock. PR #430. [confirmed: 1]
- **MagicMock attributes default to truthy MagicMock objects; boolean-checked fields must be set explicitly**: `mock = MagicMock(); if mock.running:` takes the truthy branch because `mock.running` returns a new `MagicMock` (truthy). Tests gated on `obj.running == False` or `not obj.enabled` silently take the wrong path. Fix: always set boolean fields after construction: `mock.running = False`. Same applies to any field used in boolean context (`enabled`, `active`, `is_ready`). PR #819. [confirmed: 1]
- **`MagicMock(name="foo")` sets the debug repr, NOT the `.name` attribute** -- `name=` is a reserved `MagicMock` constructor arg that controls the mock's display string (e.g., in tracebacks). To set the `.name` attribute, assign after construction: `mock = MagicMock(); mock.name = "foo"`. Tests that check `x in mock.name` or `mock.name == "foo"` silently pass for the wrong reason because `MagicMock.__contains__` defaults to `False` and attribute access returns a new mock. PR #418 CodeRabbit. [confirmed: 1]
- **`MagicMock().__truediv__()` leaks as literal filenames when evaluated against `Path.__truediv__`** -- if a test helper creates a real SQLite file at a `Path` that is actually a `MagicMock`, Python evaluates `mock_path / ".claude" / "sova.db"` and returns a `MagicMock` whose `str()` becomes `"<MagicMock name='mock.__truediv__().__truediv__()' id='...'>"`. Any code that does `open(str(path))` or `sqlite3.connect(str(path))` will create real files with those names. Gate test helpers that create real files with `assert isinstance(path, Path)` or pass `tmp_path / "subdir"` explicitly rather than a mocked path. PR #443. [confirmed: 1]
- **Mock-based gate tests cannot verify correlated SQL subqueries -- use a real DB** -- `TestRepeatedFailuresGate` mocked `scalar_one_or_none()` to return a count, so the correlated subquery (`WHERE id > (SELECT max(id) WHERE status='done')`) was never executed. CodeRabbit caught this: the test passed with incorrect SQL. Fix: add a DB-backed integration class with `sqlite+aiosqlite:///:memory:`, seed real `TaskRun` rows in failed/done/failed sequence, call the gate, assert only failures after the `done` row count. Pattern applies to any gate or service that uses a subquery for its filtering logic. PR #473. [confirmed: 1]
- **Avoid forward-anticipating dead code stubs in state maps** -- adding dict/switch entries for states that don't exist yet (e.g., `_PR_STATE_ACTIONS["merged"]`, `prStateColor("merged")`) misleads readers into thinking those paths are exercised. Neither the Python enum (`ComputedPRState`) nor `list_open_prs_with_state()` produces "merged", so both stubs are unreachable. Add enum variants and their handling together when the feature is ready; never add one without the other. PR #481 SOVA review. [confirmed: 1]
- **`test_discover_edges_batch_boundaries` is flaky under `pytest-xdist` parallel execution** -- passes consistently in isolation but fails non-deterministically in `make check` (`-n auto`). Not a real regression. Confirm with: `python3 -m pytest tests/test_knowledge.py::test_discover_edges_batch_boundaries -v`. [confirmed: 1]
- **A behavioral test that guards logic in another file must EXTRACT that logic, not re-implement it**: a test that hardcodes a copy of a workflow's shell `case` classifier (or any source-of-truth logic) is a false guard: if someone broadens the doc exclusion in the workflow, the copy stays correct and the test keeps passing, so the regression it claims to catch slips through. Extract the real block from the source at test time (e.g., anchor on `code="false"` ... `echo "code=$code"` in `sonarcloud.yml`, strip YAML indentation, run it in `bash -c`), asserting the anchors exist so extraction cannot silently degrade to matching nothing. Applies to any test whose docstring promises "exercises the same logic the CI does". Issue #857, PR #859 CodeRabbit. [confirmed: 1]
- **Structural tests that parse workflow/YAML blocks must tolerate trailing comments and match keys, not full lines**: a `_job_block` helper whose terminator required the next line to END with `:` broke on `  python-test:  # gated` (a key with a trailing comment), silently absorbing later jobs so an `if: always()` from a neighbor made the assertion pass for the wrong job. Match a 2-space-indented YAML key via regex (`^  [A-Za-z0-9_-]+:`) instead. Same principle for `count("needs: changes") >= 2`: a bare file-wide substring count is satisfied by prose comments or unrelated jobs; assert the declaration per job block instead. Issue #857, PR #859 CodeRabbit. [confirmed: 1]

## Dashboard / Frontend

- **SQL LIKE patterns in diagnostic services must match actual error strings** -- when writing LIKE patterns to categorize `TaskRun.error_message`, grep the codebase for the actual error string set by the originating step. Pattern `%non-substantive output%` silently matched zero rows because the real message is `"Development produced no substantive code changes (only: ...)"`. Also name categories after the error semantics, not the step location (e.g., `non_substantive_output` not `permission_issues`). File: `sova/dashboard/services/failure_analysis_service.py`. PR #769. [confirmed: 1]
- **Eager-load all relationships accessed in sync dict-builders** -- `_run_to_dict()` accesses `run.resource_summary` synchronously. Without `selectinload(TaskRun.resource_summary)` on every query path that feeds into it, async SQLAlchemy raises `MissingGreenlet`. The `except InvalidRequestError` handler catches it (MissingGreenlet is a subclass) but produces noisy tracebacks and silently drops data. Pattern: when a `_to_dict()` function accesses a relationship, grep ALL callers for missing `selectinload`/`joinedload` -- one path using eager loading does not protect others. File: `sova/dashboard/services/work_service.py`. [confirmed: 1]
- **SOVA review gate must fall through to PR-only lookup when issue_number is None** -- `check_integration_gates` guarded with `if not issue_number: skip`. But `get_sova_review_verdict` already handles `issue_number=None, pr_number=N` for unlinked PRs. Guard should be `not issue_number and pr_data.get("number") is None`. When updating such guards, rename the test that asserts the old skip behavior and add a new test for the PR-only path. PR #477. [confirmed: 1]
- **Daemon lifecycle ops (start/stop) need dedicated POST endpoints; UI cannot rely on config flag alone**: setting `supervisor.enabled=false` in config does not cancel the running asyncio task. Add `POST /supervisor/stop` that calls `daemon.stop()` and pops the daemon from the registry. The disable UI function should call the stop endpoint after saving config (swallow 404 if not running). Pattern: start endpoint + stop endpoint, both guarded by per-project `asyncio.Lock` to serialize concurrent enable/disable transitions. Lifecycle errors must propagate to the settings caller so the UI shows a warning toast, not a silent success. PR #477, PR #839. [confirmed: 2]
- **`_confirmPoll` intervals must be cleared in all exit paths** -- any JS interval started in one function (e.g., `enableSupervisor`) must be cleared before starting a new one, in the disable path, and in `beforeunload`. Without this, navigating away leaves the interval running. Pattern: `if (_confirmPoll) { clearInterval(_confirmPoll); _confirmPoll = null; }` as first line in disable, and in `beforeunload` handler. PR #477. [confirmed: 1]
- **Ungrouped nodes in a tier-based graph must go to tier 0, not maxTier+1** -- placing ungrouped nodes at `maxTier+1` puts them to the right of all grouped nodes. If a grouped dependent (lower tier) depends on the ungrouped node (now higher tier), `tx - sx` is negative, the bezier handle clamps to a minimum, and the arrow draws backwards. Place ungrouped nodes at tier 0 (leftmost) to preserve the left-to-right invariant. PR #477. [confirmed: 1]
- **Sort tier functions must explicitly exclude transitional states before checking group membership** -- when using a set like `_PR_STAGE_STATES` to assign a sort tier, a broader set (e.g., one that includes `pr_draft`) can inadvertently promote transitional/internal states above items that need human attention. Always add explicit early returns for states that should not be promoted: `if (item.state === 'pr_draft') return 5;` before `if (_PR_STAGE_STATES.has(item.state)) return 2;`. The sort-tier function and the filter set may diverge from server-side ordering when a new state is added; verify both sides. PR #479. [confirmed: 1]
- **Agent re-run functions must pass `prNumber` through to the start call** -- `rerunAgent(issue, role, prNumber)` receiving `prNumber` from `data-pr` but ignoring it in the body means a re-run of a developer run that had an open PR skips `pr_number` in the API payload. Without it, the agent assesses fresh rather than entering the address-review pipeline. Always pass through: `_doStartAgent(issue, role === 'auto' ? null : role, false, prNumber || null)`. Server-side `_recover_last_pr_number()` provides a partial fallback but is not guaranteed. PR #479. [confirmed: 1]

- **Badges use `rounded-full`, buttons use `rounded`** -- visual distinction between read-only state indicators (pills) and clickable actions (rectangles). Badges: `px-2 py-0.5 rounded-full`. Buttons: `px-3 py-1 rounded`. Without this, users can't tell what's clickable. [confirmed: 1]
- **Range slider max must match Pydantic field constraint (le=N)** -- if slider HTML has `max="10"` but the backend Pydantic model accepts `le=20`, users can never reach the valid upper range via the UI. Always align front-end widget bounds (`min`, `max`) with backend validation bounds (`ge`, `le`). PR #298. [confirmed: 1]
- **Fixed-width columns for right-aligned badge/button groups** -- wrap PR badge, state badge, and action button in a fixed-width container (e.g., `style="width:340px"`) with internal fixed-width divs. Without this, variable text widths cause ragged vertical alignment across rows. [confirmed: 1]
- **Multi-action handoffs expand into a sub-row, not cramped inline** -- single-action handoffs (e.g., "Integrate PR") render on the main row. Multi-action handoffs (e.g., spec review with 4 buttons) expand into a second line below the title with summary text + buttons. [confirmed: 1]
- **SonarCloud coverage requires unit tests for service-layer branches, not just API-level tests**: API-level tests via `AsyncClient` cover router code but may miss service-layer branches (cache TTL paths, symlink rejection, drift detection). Add direct unit tests for service functions (e.g., `_command_entry_to_dict`, `get_command_detail`) to cover all branches. PR #886. [confirmed: 1]
- **Deduplicate overlapping polls via `window._sova*` shared caches** -- when multiple JS modules poll the same endpoint (sidebar + page-specific), have the primary poller store its response in `window._sovaActiveAgents = {data, ts}` (or `window._sovaSystemMetrics`). Secondary consumers read from the cache with a staleness check (`Date.now() - cached.ts > 5000`). Server-side: add a `_metrics_cache` tuple with `time.monotonic()` + threading lock + 3s TTL on blocking functions like `get_system_metrics()`. PR #595. [confirmed: 1]
- **Save-poll race guard must cover ALL mutation paths, not just the primary save** -- when adding `_queueSaveInFlight` + `_queueLastSaved` grace period to prevent polling from overwriting just-saved state, the guard was initially only applied to `saveQueue()`. The review caught that `addToQueue()`, `removeFromQueue()`, and `clearQueue()` use separate API endpoints but write to the same underlying state, so they need the same `_queueLastSaved = Date.now()` timestamp. General rule: when guarding a race condition between polling and mutation, enumerate ALL functions that mutate the shared state. File: `sova/dashboard/templates/supervisor.html`. PR #656. [confirmed: 1]
- **Clickable card pattern: cursor-pointer + stopPropagation on nested buttons** -- add `cursor-pointer hover:opacity-80` on clickable element with `onclick`. All nested interactive elements must call `event.stopPropagation()`. File: `sova/dashboard/templates/agents.html`. [confirmed: 1]
- **Extract shared CAS patterns to avoid SonarCloud duplication gate** -- when multiple functions share validation + atomic CAS update logic (e.g., `resume_from_approval` and `reject_spec`), extract a shared helper parameterized by target status. Without this, the duplicated block triggers SonarCloud's 3% new code duplication threshold. PR #334. [confirmed: 1]
- **DB-level tests needed for functions mocked in router tests** -- router tests that mock service functions (e.g., `reject_spec`, `_find_awaiting_approval_run`) provide integration coverage for the router but leave the service function at 0% coverage. Add separate DB-level tests that seed TaskRun records and call the service directly. PR #334: coverage went from 35.8% to 95.6%. [confirmed: 1]
- **Update redirect chains when consolidating pages** -- when page A merges into B and old routes C,D redirected to A, update C,D to redirect to B. Also update sidebar nav, back-links, "View all" links, architecture.md page counts, and delete dead templates. [confirmed: 1]
- **Track notified IDs, not state transitions, for completion alerts** -- track seen `run_id`s to avoid missed/duplicate completion notifications. [confirmed: 1]
- **Disable async action buttons during operations** -- set `button.disabled = true` at function start, re-enable in `finally`. [confirmed: 1]
- **Wrap all API cost values with `parseFloat()` before `.toFixed()`** -- `Decimal` serializes as strings, `"0.000000".toFixed(2)` throws TypeError. Always `parseFloat(value || 0).toFixed(N)`. [confirmed: 1]
- **No nested `<a>` tags** -- use `issueOrPrLabel()` (`<span>`) inside `<a>` containers, `issueOrPrLink()` (`<a>` + stopPropagation) inside `<div onclick>`. [confirmed: 2]
- **Gate secondary badges when primary label shows same entity** -- suppress duplicate PR badge when PR is already in the issue label position. PR #408. [confirmed: 1]
- **marked.js v15 heading renderer uses token object** -- `heading({ tokens, depth })` not `heading(text, level)`. [confirmed: 1]
- **Key-based cache prevents re-render on every poll** -- store a key string from computed metrics; only rebuild DOM when the key changes. Pattern: `var key = values.join(','); if (key === _lastKey) return; _lastKey = key;`. Used in `renderPrSummary()` for PR metrics strip. [confirmed: 1]
- **Always add `type="button"` to `<button>` elements in dashboard templates** -- without an explicit type, browsers default to `type="submit"`. Harmless when standalone but breaks form submissions if buttons ever land inside a `<form>`. CodeRabbit (HTMLHint) flags this as a warning; adding `type="button"` silences it and prevents future regression. PR #480. [confirmed: 1]
- **Offset-aware UTC datetimes must normalize to Z-suffix before sending to JS** -- Problem: `datetime.isoformat()` on an offset-aware datetime (e.g., `datetime.now(timezone.utc)`) produces `"2026-07-26T08:01:13+00:00"`. JS that guards with only `!ts.endsWith('Z')` appends `Z`, producing unparseable `...+00:00Z`. Fix: in Python, emit `dt.isoformat().replace("+00:00", "Z")`. JS guard: use a regex to detect any timezone offset suffix: `const utcTs = ts && !/[+-]\d{2}:\d{2}$/.test(ts) && !ts.endsWith('Z') ? ts + 'Z' : ts`. - **`paths-ignore` STRANDS required checks in a ruleset (use the gate-job pattern instead)**: when a required check is enforced by a repo *ruleset* (not classic branch protection), a workflow skipped via `paths-ignore` never reports that check's context at all, so the PR sits `BLOCKED` forever waiting on a check that will never arrive. ## Architecture / Layering

- **Injected dependencies must validate not-None at construction time (fail-fast)** -- when refactoring from a lazy import to constructor injection (e.g., `command_dispatcher` on `DAGExecutor`), add `if param is None: raise ValueError(...)` in `__init__`. Without this, `None` passes silently at construction and raises a confusing `AttributeError` deep in `_execute_node()`. Tests for the missing-argument case (`TypeError`) do not cover the `None` case. PR #783 CodeRabbit review. [confirmed: 1]
- **Import boundary AST tests should use `ast.walk()` for recursive checking** -- `ast.iter_child_nodes()` only checks module-level imports; function-local `from sova.dashboard import X` bypasses the check entirely. Use `ast.walk(tree)` to recursively check all `Import` and `ImportFrom` nodes at any nesting depth. Also handle `SyntaxError`/`UnicodeDecodeError` explicitly (skip with warning) rather than swallowing silently with empty return. File: `tests/test_import_boundaries.py`. PR #783. [confirmed: 1]

## Auto-Retry / Failure Classification

NOTE: Auto-retry system removed in migration 020 (2026-07-20). `_schedule_retry()`, `classify_failure()`, `_RECOVERABLE_PATTERNS`, `retry_of_id`, `retry_count` no longer exist. Architecture.md corrected. Patterns below preserved for future re-implementation (issues #343, #344). When agents fail, the user must restart manually from the dashboard.

- **HTTP status code patterns need "http " prefix to avoid false positives** -- bare "502" matches file paths and PIDs. PR #343. [confirmed: 1]
