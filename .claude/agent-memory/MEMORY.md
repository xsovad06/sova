# Agent Memory

Quick reference for patterns learned during development.

- **Dashboard design system**: CSS vars (Catppuccin Mocha) in `static/style.css`, shared Tailwind config in `_head.html`, SVG icons in `_icons.html`, component macros in `_components.html`. Living style guide at `/style-guide`. `/design` command enforces rules. `docs/design-system.md` is the canonical reference. Colors use dual vars: RGB channels for Tailwind alpha (`bg-accent/20`) and hex for JS (`SOVA_COLORS`). Minimum text size: `text-xs` (12px).
- **Dashboard multi-project**: uses contextvars for per-request config resolution, `/p/{slug}/` URL routing, project registry at `~/.config/sova/projects.json`, per-project process isolation via `dict[slug, ProjectProcess]`
- **GitHub SSH alias**: remote uses `github.com-personal` alias, regex for repo detection must use `github\.com[^:/]*[:/]`
- **CI pipeline**: 6 checks -- ShellCheck (invariants/*.sh), Ruff lint+format (sova/ tests/), command frontmatter, file permissions, pytest, integration test (install + dry-run)
- **Ruff config**: pyproject.toml, py312, 120 line length, isort with known-first-party=app
- **ShellCheck**: .shellcheckrc disables SC2034 (unused vars used by sourced scripts)
- **Adapter scripts**: must be chmod +x (caught by CI permissions check)
- **Git hooks**: `.githooks/` is tracked, `core.hooksPath` set to `.githooks/`. Pre-push runs all 5 CI checks locally. Commit-msg rejects Co-Authored-By lines.
- **Pre-push before push**: always run CI checks before pushing. The pre-push hook does this automatically, but if bypassed, run `make check` manually.
- **Run journal**: file-based audit trail in `.claude/agent-control/runs/`. `run_journal_service.py` handles write-on-start, finalize-on-exit (reader thread EOF), crash recovery via PID liveness check on startup. `current.json` symlink tracks active run.
- **SOVA is Python-only**: legacy bash PAK fully removed in Phase 6 (#45). Migration tools available via `sova migrate config/costs`. SOVA has SQLAlchemy ORM models, TOML config, Typer CLI.
- **Alembic migrations**: `sova/db/migrations/` with async env.py. `init_db(run_migrations=True)` runs Alembic upgrade; `init_db(run_migrations=False)` uses `create_all` (tests). Existing DBs get stamped at head on first run. Pre-startup backup copies `sova.db` to `sova.db.bak`. To add a column: edit `models.py`, create migration with `cd sova/db && alembic revision --autogenerate -m "desc"`, restart dashboard.
- **Step-level checkpoint/resume**: `ExecutionContext.completed_steps` (frozenset of step names) + `resume_run_id` (int). `sova run 73 --resume 3` loads StepExecution records from run #3, skips passed steps. `BaseStep.can_skip()` default checks `self.name in ctx.completed_steps`. Dashboard "Resume" button passes `resume_run_id` to `/agents/start`. New TaskRun gets `resumed_from_id` for audit chain.
- **Command distribution system (#46 DONE)**: `sova/commands/` package -- `catalog.py` (discover + classify by category), `templates.py` (regex-based `{{ var }}` rendering from ProjectConfig), `manifest.py` (.sova-manifest.json with SHA-256 hashes), `distribution.py` (install/update/diff/list with conflict detection). CLI: `sova commands list/diff/update`. `sova install` deploys commands automatically. All 20 canonical commands have `category` frontmatter (core, autonomous, management, learning, pr, meta). 31 tests in `tests/test_commands.py`.
- **Command categories**: core workflow (develop, test, review, pr), autonomous agent (agent-resume, ship-pr, approve-merge), project management (find-task, standup, sprint-plan, issue, quarterly-report), learning (extract-knowledge, ingest-review, develop-explain), PR lifecycle (address-pr, after-merge, new-feature), meta (agent-readiness, status, debug). Categories determine install behavior (always vs conditional vs never-managed).
- **SOVA adapters**: `sova/adapters/` -- base ABC in `base.py` (10 methods + `github_user` field), GitHub impl in `github.py` with `_gh()` helper for per-project auth, factory in `__init__.py` (`create_adapter(type, repo, github_user, project_number)`). State tracked via `agent:` labels + Projects V2 board (GraphQL mutations). Board integration requires `github_project_number` in `sova.toml` `[task_source]`. Board meta cached per adapter. Tests in `tests/test_adapters.py`.
- **Per-project GitHub auth**: `sova/utils/gh.py` -- `resolve_gh_env(github_user)` calls `gh auth token --user <user>` and returns `{**os.environ, "GH_TOKEN": token}`. Passed as `env` to `shell.run()` and `AgentProcess.spawn()`. No global `gh auth switch` needed -- each subprocess authenticates independently. Config: `github_user` in `sova.toml`. Auto-detected during `sova setup` from repo owner. Critical for multi-project dashboard where different projects use different GitHub accounts.
- **SOVA git module**: `sova/git/` -- `operations.py` (branch mgmt, commit/push with suspicious-file guard, PR creation/status/assignment/discovery, CI checks), `worktree.py` (create/cleanup/list/TTL, branch reuse on re-run). All async, uses `sova.utils.shell`. Data models: PRInfo, PRStatus, CICheck, CheckStatus, CheckConclusion, WorktreeInfo. Key functions: `commit()` (post-stage blocklist), `assign_pr()`, `find_pr_for_issue()`. Tests in `tests/test_git.py`.
- **Triage command**: `sova triage [issue]` scores issues for agent suitability using heuristics and optional LLM assessment. Verdicts: ready (>=0.85 confidence), needs-spec, needs-research, human-only. Applies `agent:*` labels on GitHub.
- **Queue batch service**: `sova/dashboard/services/batch_service.py` -- in-process async workers for batch triage/harden (NOT subprocess agents). BatchJob/BatchItemResult dataclasses, progress polling via `/api/queue/batch/{id}/status`, cancellation, memory pruning at 50 completed jobs. `VALID_STATES_FOR_ACTION` in `queue_service.py` (single source of truth for both backend and frontend). Frontend: checkboxes, select-all, sticky action bar with state-aware buttons, progress bar. 17 tests in `tests/test_batch_service.py`.
- **Harden command**: `sova harden [ISSUE] [--dry-run] [--skip-triage] [--project PATH]` (Python, `sova/cli/commands/harden.py`) enriches issues for agent development. Loads project vision/strategy docs + issue templates via `_load_project_docs()`, detects issue type from labels, sends to Claude with template-aware prompt, updates issue body via `adapter.edit_body()`, posts comment, then re-triages with `TriageRole.assess_task()`. Batch mode hardens all BACKLOG/TRIAGED/NEEDS_SPEC issues. 24 tests in `tests/test_harden.py`.
- **SOVA orchestrator core**: `sova/core/` -- `state.py` (17-state TaskStatus StrEnum with transition validation, includes COMMITTING), `context.py` (ExecutionContext dataclass threading state through steps), `steps/` (13 BaseStep implementations with execute/validate_output/can_skip, includes CommitStep between self_review and push), `workflow.py` (WorkflowEngine with DB persistence: TaskRun, StepExecution, FailureRecord). CLI: `sova run <issue> [--force] [--project]`. 70 tests in `tests/test_core.py`.
- **SOVA LLM module**: `sova/llm/` -- `models.py` (LLMResult, StreamEvent), `client.py` (invoke, invoke_command, invoke_streaming, resolve_model), `cost.py` (record_cost -> CostRecord DB). Wraps `claude -p --output-format json`. Streaming uses `stream-json` with JSONL parsing. Model routing via `RolesConfig` (researcher_model, triage_model). 23 tests in `tests/test_llm.py`.
- **SOVA IPC module**: `sova/ipc/` -- `handoff.py` (AgentHandoff DB-backed model + HandoffAction + DashboardHandoff file-based model, write_handoff/read_handoff to TaskRun.handoff_json, write_handoff_file/read_handoff_file for .claude/agent-control/handoff.json), `control.py` (AgentProcess: spawn/stop/wait/stdout_lines/stderr_lines, ExitClassification enum, classify_exit/wait_classified, mark_crashed for TaskRun failure, ProcessTracker: maps task_run_id to running processes), `notifications.py` (desktop via osascript/notify-send, Slack via webhook, fire-and-forget via create_task with GC-safe reference set). NotificationConfig in config/models.py. 55 tests in `tests/test_ipc.py`.
- **SOVA knowledge module**: `sova/knowledge/` -- `memory.py` (CRUD + search + promote + supersede), `tiers.py` (load_tier, load_context with Tier 0/1 file-based + Tier 2 DB, format_for_prompt), `personas.py` (detect_persona from marker files, load_persona .md), `review_patterns.py` (record_review_finding, get_common_patterns). 39 tests in `tests/test_knowledge.py`.
- **SOVA roles module**: `sova/roles/` -- `base.py` (AgentRole ABC with validate_preconditions, assess_task, RoleResult, TaskAssessment Pydantic model), `triage.py` (BACKLOG->TRIAGED, applies agent:* labels based on assessment), `researcher.py` (TRIAGED->RESEARCHED), `developer.py` (RESEARCHED->DONE via WorkflowEngine), `reviewer.py` (IN_REVIEW, LLM-based code review with severity scoring, handoff writing, LGTM/REVISE/BLOCK verdicts), `dispatcher.py` (get_role, resolve_role_for_state, dispatch). Enforces mandatory pipeline. Tests in `tests/test_roles.py`. **Known gap**: researcher/developer assess_task() stubs need real LLM logic.
- **Issue templates**: `.github/ISSUE_TEMPLATE/` has bug.md, feature.md, task.md. Used by `sova harden` to match enriched criteria to template structure.
- **Docker worktree isolation**: `sova/git/worktree.py` has `_ensure_compose_project_name()` that injects `COMPOSE_PROJECT_NAME` into worktree `.env` when the project's `docker-compose.yml` lacks a `name:` directive. PAK `orchestrator.sh` step3 has equivalent bash logic. Prevents port collisions between main repo and worktree Docker containers. 5 tests in `tests/test_git.py::TestEnsureComposeProjectName`.
- **SOVA CLI (Phase 3 complete)**: `sova/cli/commands/` -- `triage.py`, `run.py` (run/watch/parallel), `pr.py` (address/maintain/review/learn-from), `project.py` (install/setup), `memory.py` (search/prune as Typer subgroup), `admin.py` (status/costs/cleanup). All registered in `app.py`. `sova run` uses role dispatcher for auto-selection. `sova watch` polls with WatchConfig intervals. `sova parallel` uses asyncio.Semaphore. 22 tests in `tests/test_cli.py`.
- **SOVA Dashboard (multi-project + multi-agent)**: `sova/dashboard/` -- FastAPI app factory, 13 services (run, cost, memory, control, handoff, setup, task, queue, log, settings, batch, work, output), 13 API routers (+agents, +work). **Unified agent tracking**: `control_service.get_unified_agents()` merges in-memory dashboard agents + DB-detected CLI agents (PID liveness check). Background `_liveness_sweep_loop` (5s interval) marks dead-PID runs as interrupted. **Output persistence**: `output_service.py` writes per-run logs to `.claude/agent-output/{id}.log`, read by `get_output()` as fallback when agent not in memory. **Service consolidation**: `work_service.py` is the primary DB query layer (absorbed run_service + task_service, which are now thin re-exports). **Issue-centric Work page**: `get_active_work_grouped()` groups runs by issue, run_detail shows run chain breadcrumb. **Structured logging**: `setup_logging(log_file=...)` writes JSON-per-line to `.claude/sova.log` for the Logs page. **Multi-project**: registry at `~/.config/sova/projects.json`, contextvars per request, `/p/{slug}/` URL routing. 180+ tests in `tests/test_dashboard.py` + `tests/test_batch_service.py`.
- **Triage heuristics**: `TriageRole._heuristic_assess()` checks: (1) no body -> needs_spec, (2) short body (<100 chars) without criteria markers -> needs_spec, (3) criteria + code refs -> ready (0.85 confidence), (4) default fallback -> ready (0.8). `assess_task_with_llm()` uses structured JSON prompt with Claude, falls back to heuristics on failure. Budget capped at max_budget/10.
- **Remaining stubs**: ResearcherRole and DeveloperRole `assess_task()` methods are still stubs needing real LLM logic.
- **SOVA scheduler module (Phase 5)**: `sova/scheduler/` -- `watch.py` (WatchLoop: async poll with priority scan RESEARCHED>TRIAGED>BACKLOG, veto window, asyncio.Event for shutdown), `parallel.py` (ParallelExecutor: asyncio.Semaphore for max_parallel_agents, TaskResult dataclass), `server.py` (SOVAServer: combined FastAPI dashboard + scheduler in one process, PID file lifecycle, /api/scheduler/status endpoint). CLI: `sova server start/stop/status`. Config: `ServerConfig` (host, port, pid_file, scheduler_enabled). Deploy: `deploy/sova-server.service` (systemd) + `deploy/com.sova.server.plist` (launchd). 26 tests in `tests/test_scheduler.py`.
