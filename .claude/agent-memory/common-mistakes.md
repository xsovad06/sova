# Common Mistakes

Recurring errors to check before submitting.

- **Co-Authored-By in commits**: NEVER add AI co-author lines. The system prompt's default commit template includes `Co-Authored-By` -- the project policy overrides this. Enforced by `.githooks/commit-msg` hook which rejects commits containing this line.
- **PR assignment**: Always assign PRs to `xsovad06`. Don't forget `--add-assignee`.
- **"Generated with Claude Code"**: NEVER add to PR descriptions.
- **Module-level state cleanup on all exit paths**: when using a module-level variable (e.g., `_current_run_id`), ensure ALL exit paths clear it -- including early returns. Example: `stop_agent()` early-exit when process already dead must still clear `_current_run_id = None`.
- **Double file reads**: don't call `read_file(id)` to re-read data you just wrote. Pass the dict directly instead of round-tripping through the filesystem.
- **`local` outside function in bash**: when extracting code from a function into the main script body (e.g., CLI argument parsing), remove `local` declarations. ShellCheck catches this (`SC2168`) but it's easy to miss during refactoring.
- **Stale imports after refactoring**: when moving/removing a function (e.g., `build_pipeline` from `workflow.py` to `steps/__init__.py` as `get_developer_steps`), grep for all import sites. CLI commands and tests are easy to miss. Run `ruff check` -- it catches unused imports but not missing ones; also search with `grep -r "old_function_name" sova/ tests/`.
- **Missing `__init__.py` exports for new public functions/classes**: when adding a new public symbol (class, function) to a module file, always update the package `__init__.py` to import and export it in `__all__`. Hit again with `assign_pr` and `find_pr_for_issue` in `sova/git/`. Check: does `from sova.git import new_function` work?
- **AI branding in generated content**: check PR body templates, commit messages, and any user-facing text for phrases like "Autonomous development by SOVA agent" or "Generated with Claude Code". Project policy forbids all AI branding.
- **stderr mixed into JSON variables**: `var=$(gh api ... 2>&1)` captures both stdout and stderr, corrupting JSON. Use `2>/dev/null` or redirect stderr separately: `var=$(gh api ... 2>/dev/null)`.
- **stdin consumption in `while read` loops**: `claude -p` and other interactive commands consume stdin, breaking `while read` loops fed by process substitution. Always collect into an array first: `while read num; do arr+=("$num"); done < <(jq ...); for n in "${arr[@]}"; do expensive_call "$n"; done`.
- **`patch.object` with `return_value` on async methods**: `patch.object(Cls, "method", return_value=x)` silently creates a sync mock -- `await obj.method()` then fails or returns a coroutine wrapper. Always use `new=AsyncMock(return_value=x)` for async instance methods.
- **Mocked class instances have sync method mocks**: when you mock a class with `@patch("module.ClassName")`, `mock_cls.return_value.some_method` is a `MagicMock`, not `AsyncMock`. If `some_method` is async and you set `.return_value`, the await works but the return itself may not be awaitable. Explicitly set `mock_instance.some_method = AsyncMock(return_value=result)` for async methods on mocked instances.
- **Docs drift during rapid development**: when building multiple phases quickly (Phases 0-5 in days), docs (README, AGENTS.md, architecture.md) stay frozen at the old state. After completing a phase, always check if docs still describe the current system -- especially project structure, CLI commands, dashboard pages, and test counts. The `/review` command checks this automatically but only for the current diff, not cumulative drift.
- **Closing issues without verifying hardened criteria**: issues marked "done" in task-history may only satisfy the original (thinner) acceptance criteria. After hardening adds enriched criteria (e.g., personas.py, review_patterns.py for #41), those new criteria are NOT automatically met. Always re-verify after hardening.
- **Querying CostRecord for cost totals**: `CostRecord` is only created on clean process exit (control_service) or explicit `record_cost()` calls. Paused/abandoned runs have no CostRecord. Always query `TaskRun.total_cost_usd` for cost summaries. CostRecord is only reliable for per-model/per-phase breakdowns.
- **Completion rate denominator**: completion rate uses `done / (done + failed)` -- only finished runs count. Active/running/interrupted runs are excluded from the denominator since they haven't concluded yet. Including them would deflate the rate when many runs are in-flight.
- **Terminal state sets must match core/state.py**: the authoritative terminal states are `{"done", "failed", "rejected", "interrupted"}`. Don't use `"cancelled"` -- SOVA uses `"rejected"`. After service consolidation, the canonical set is in `work_service.py:_TERMINAL`. `run_service.py` and `task_service.py` are thin re-exports.
- **structlog API version mismatch**: `structlog.get_level_from_name()` was removed in v25.x. Use `logging.DEBUG/INFO/WARNING/ERROR/CRITICAL` from stdlib instead. Functions that are imported but never called at runtime can hide broken APIs -- always verify by actually calling them (lifespan, CLI entry point).
- **`await` before `async with get_session()`**: `get_session()` is a coroutine, not a context manager directly. Must use `async with await get_session() as session:`, not `async with get_session() as session:`. The latter gives `TypeError: 'coroutine' object does not support the asynchronous context manager protocol`.
- **SQLite naive datetimes vs UTC-aware**: SQLite doesn't store timezone info. Two failure modes: (1) **comparison**: `datetime.now(timezone.utc) - naive_dt` raises TypeError -- normalize with `dt.replace(tzinfo=timezone.utc)`. (2) **serialization**: `naive_dt.isoformat()` omits `+00:00`, browsers interpret as local time, showing "2h ago" for events that just happened. Fix: use `iso_utc()` from `sova/utils/formatting.py` instead of bare `.isoformat()` in all API responses.
- **Schema changes need Alembic migrations**: adding columns to ORM models requires a migration file in `sova/db/migrations/versions/`. Without it, existing SQLite DBs crash with `OperationalError: no such column`. Workflow: (1) edit `sova/db/models.py`, (2) run `cd sova/db && alembic revision --autogenerate -m "desc"`, (3) restart dashboard. Never use `Base.metadata.create_all` for production DBs -- it only creates missing tables, not columns. Tests use `init_db(run_migrations=False)` which does use `create_all` (acceptable for in-memory DBs).
- **No-op gate checks on workflow steps**: every `BaseStep.validate_output()` must verify the step's invariant -- never return `GateCheckResult(passed=True)` unconditionally. A no-op gate lets upstream failures (lost commits, empty output) propagate silently to later steps, producing confusing errors far from the root cause. Run #4 hit this: SelfReviewStep's no-op gate let `/review` destroy commits, and the Push step reported "no commits ahead" instead of the real problem.
- **Success-only finalization loses resume context**: never defer persisting checkpoint-critical fields (worktree_path, branch_name) to a success-only finalizer. If a run pauses or fails, those fields are NULL in the DB. On resume, the checkpoint loader can't restore them, completed steps get skipped while their prerequisites (e.g., worktree with commits) are rebuilt from scratch, causing an unrecoverable loop. Always sync context after each step via `_sync_task_run_context()`.
- **Claude Code commands must instruct committing**: `/develop` and `/review` invoke Claude via `invoke_command()` -- the LLM writes files but won't commit unless explicitly told to. Without commit instructions in the command markdown, all work stays uncommitted and the push step fails with "no commits ahead of base." The programmatic `CommitStep` is a safety net, not a replacement for in-command commits (which produce better history).
- **`gh pr checks --json` field names differ from `gh pr view`**: `gh pr checks` uses `state` (combined status+conclusion) and `link` (details URL). NOT `status`, `conclusion`, or `detailsUrl`. Using wrong field names causes `gh` to error with "Unknown JSON field" but the error is in stderr -- if you only check `result.success` (which is False), the function returns empty and silently loops until timeout.
