# Learnings

Framework gotchas, debugging insights, and development patterns.

- **Legacy file migration pattern**: when renaming internal files, provide a migration command (e.g., `sova migrate config`) that converts old config formats to new ones. Keep legacy parsing code in the config loader module under a clear section comment so migration commands can reuse it without duplication. [confirmed: 0]
- **System prompt vs project policy conflicts**: the Claude Code system prompt includes default behaviors (e.g., Co-Authored-By in commits) that may conflict with project rules in AGENTS.md. Git hooks are the reliable enforcement mechanism since they block at the git level regardless of what the AI generates. [confirmed: 0]
- **Dashboard update_only passthrough**: when adding new flags to `install.sh`, remember to also update `InstallRequest` in `setup.py` and the `installProject()` JS function in `setup.html` -- three places need to stay in sync. [confirmed: 0]

- **FastAPI lifespan vs on_event**: `@app.on_event("startup")` is deprecated in modern FastAPI. Use `@asynccontextmanager async def lifespan(app)` passed to `FastAPI(lifespan=lifespan)`. [confirmed: 1]

- **`git worktree add` creates the target directory**: do NOT pre-create the worktree directory with `mkdir` -- git does this itself and may fail if the directory already exists. Only ensure the **parent** directory exists: `worktree_path.parent.mkdir(parents=True, exist_ok=True)`. [confirmed: 0]
- **Avoid misleading unused parameters**: if a function accepts a parameter it never uses, callers assume it has an effect. Either implement it or remove it. In the worktree TTL case, `ttl_paused_days` was accepted but ignored -- simplified to a single `ttl_days` param. [confirmed: 0]

- **Streaming vs batch subprocess patterns**: `sova.utils.shell.run()` captures all stdout at once (batch mode). For line-by-line streaming (e.g., dashboard live output), use `asyncio.create_subprocess_exec()` directly with `stdout=PIPE` and `readline()` loop. This is not duplication -- the use cases are fundamentally different. [confirmed: 0]
- **Async generator return type**: annotate async generator functions as `-> AsyncIterator[T]` (not `AsyncGenerator`). This is the PEP 484 convention and matches how callers consume them (`async for x in func()`). The function itself yields, but the return annotation describes the protocol. [confirmed: 0]
- **stdin consumption in bash batch loops**: `claude -p` (and other interactive tools) read stdin, which steals data from `while IFS= read -r line; do ... done < <(...)` loops. Fix: collect all items into an array first, then iterate with `for item in "${arr[@]}"`. [confirmed: 0]
- **Git worktree `--git-dir` returns relative paths**: for worktrees, `git rev-parse --git-dir` returns paths like `../../.git/worktrees/33`. Use `--absolute-git-dir` (git 2.13+) or resolve with `cd "$wt_dir" && git rev-parse --git-dir` and prepend `$wt_dir/` if relative. [confirmed: 0]

- **Agent-ready issue templates**: research shows 5 essential fields for agent success: (1) concrete problem/feature with input/output examples, (2) file/module hints, (3) command-verifiable acceptance criteria, (4) out-of-scope constraints (prevents 23% of agent PR failures), (5) references to related code/tests. Anti-pattern: subjective criteria like "code is clean" — agents cannot self-verify these. [confirmed: 0]
- **`patch.object` on async methods needs `new=AsyncMock()`**: `patch.object(MyClass, "async_method", return_value=result)` creates a sync MagicMock, breaking `await` calls. Use `patch.object(MyClass, "async_method", new=AsyncMock(return_value=result))` instead. This is different from `patch("module.func", new_callable=AsyncMock)` which works correctly because it creates the mock from scratch. [confirmed: 0]
- **AppleScript injection via f-string interpolation**: when building osascript commands with user-provided strings (notification title/message), escape backslashes and quotes before interpolation: `safe = text.replace("\\", "\\\\").replace('"', '\\"')`. Without this, a title containing `"` breaks the AppleScript or could execute arbitrary commands. [confirmed: 0]
- **`**kwargs` type hint for mixed-value dicts**: annotate `**fields: object` (not `**fields: str`) when values can be str, int, or None. The `str` annotation misleads callers. Example: `async def update(id: int, **fields: object) -> Model | None`. [confirmed: 0]
- **Two DB session patterns in SOVA**: (1) `async with await get_session() as session:` -- auto-closes session on exit, cleaner for CRUD operations (`knowledge/memory.py`). (2) `session = await get_session()` + `async with session.begin():` -- explicit transaction control, used in `workflow.py` and `handoff.py`. Both work; pattern (1) is preferred for new code. [confirmed: 0]
- **Hardened != implemented**: `sova harden` enriches issue descriptions but does not verify code. Always verify hardened acceptance criteria against actual code before closing an issue. Pattern: read each acceptance criterion, grep/read the corresponding code, report DONE/PARTIAL/MISSING per criterion. [confirmed: 0]
- **Structural vs LLM-dependent code**: role implementations (triage, researcher, reviewer) follow a pattern where structural code (state transitions, dispatcher routing, Gate 3 enforcement) gets built first and LLM-dependent logic (actual codebase investigation, PR review analysis) remains as stubs. This is intentional -- stubs get real logic when integrated with the LLM client in end-to-end runs. [confirmed: 0]
- **Phase dependency analysis for parallelism**: to identify parallel work, read `docs/REWRITE-PLAN.md` phase definitions. Issues within the same phase can run in parallel if they don't share modules. Cross-phase issues are sequential. Dependencies are documented in issue bodies ("Dependencies" section) and in the plan's phase descriptions. [confirmed: 0]
- **Gap-closing prompts**: when an issue is 60-80% done, write focused prompts listing only the missing items with exact file paths, function signatures, and test expectations. This is more effective than re-running the full development workflow -- avoids rework on already-done code and keeps the scope tight. [confirmed: 0]
- **Default tier filters on aggregate queries**: when a function combines multiple knowledge sources (file-based + DB), unfiltered DB queries (`tier=None`) silently return all tiers, mixing DB-backed shared memories with file-based shared content. Default to `tier="project"` when no filter is specified, since Tier 0 (shared) and Tier 1 (rules) are already loaded from files. [confirmed: 0]
- **`asyncio.create_task()` without held reference**: tasks created with `create_task()` can be garbage-collected before completion if no reference is kept. Fix: maintain a module-level `set[asyncio.Task]` and use `task.add_done_callback(tasks.discard)` to auto-clean. Pattern: `_bg = set(); task = asyncio.create_task(coro); _bg.add(task); task.add_done_callback(_bg.discard)`. Found in `sova/ipc/notifications.py` fire-and-forget dispatch. [confirmed: 0]
- **Docker Compose project name collision in worktrees**: when `docker compose up` runs from a worktree at `.claude/worktrees/{N}/`, Docker derives project name from directory basename (e.g., `60`), creating separate containers that try to bind the same host ports. Fix: (1) target projects should add `name: <project>` to their `docker-compose.yml`, (2) SOVA's `_ensure_compose_project_name()` in `sova/git/worktree.py` injects `COMPOSE_PROJECT_NAME` into the worktree `.env` as a fallback when no `name:` directive exists. [confirmed: 0]
- **Label taxonomy**: SOVA uses `agent:ready/needs-spec/needs-research/human-only` labels for triage results, plus `agent:triaged/researched/in-progress/in-review` for workflow state. Target repos need these labels created before triage works (see `sova install`). [confirmed: 0]
- **Typer command registration via `app.command(name=)(func)`**: use `app.command(name="my-cmd")(my_func)` to register functions defined in separate modules. For subcommand groups, create a separate `typer.Typer(name="group")` in the module and use `app.add_typer(group_app)` in the main app. Both patterns used in `sova/cli/app.py`. [confirmed: 0]
- **Typer `no_args_is_help` exit code**: different Typer versions return exit code 0 or 2 when `no_args_is_help=True` and no args are provided. Tests should accept both: `assert result.exit_code in (0, 2)`. [confirmed: 0]
- **ASGI test client pattern**: use `httpx.AsyncClient(transport=ASGITransport(app=app))` for testing FastAPI apps. Override DB session by reassigning the global engine/session factory in `sova.db.session` module before tests. In-memory SQLite: `sqlite+aiosqlite://`. [confirmed: 0]
- **RedirectResponse returns 307 not 200**: FastAPI's `RedirectResponse` defaults to HTTP 307. Tests must check for `status_code == 307` and inspect `response.headers["location"]`, not expect 200. [confirmed: 0]
- **SQL GROUP BY vs Python-side aggregation**: for time-based aggregations (e.g., daily cost totals), use `func.date(Column)` in SQL GROUP BY rather than fetching all rows and grouping in Python with defaultdict. Much more efficient, especially with large datasets. [confirmed: 0]
- **`AsyncIterator[None]` for lifespan**: `@asynccontextmanager` async functions should be annotated as `-> AsyncIterator[None]`, not `AsyncGenerator[None]`. The generator distinction (`AsyncGenerator[YieldType, SendType]`) requires two type params and is semantically wrong for context managers. [confirmed: 0]
- **StrEnum values match strings but prefer enum**: `TaskState` is a `StrEnum`, so `task.state == "backlog"` works but is fragile -- use `task.state == TaskState.BACKLOG` for type safety and IDE support. Caught in review of watch mode's actionable-task filter. [confirmed: 0]
- **FastAPI lifespan wrapping**: to add lifecycle hooks to an existing app without replacing its lifespan, capture `app.router.lifespan_context`, wrap it, and reassign. Pattern: `original = app.router.lifespan_context; @asynccontextmanager async def combined(app): async with original(app): yield; app.router.lifespan_context = combined`. Used in `sova/scheduler/server.py` to add scheduler start/stop around dashboard DB init. [confirmed: 0]
- **Regex over Jinja2 for simple `{{ var }}` substitution**: for template files with only variable replacement (no conditionals/loops), `re.sub(r"\{\{\s*(\w+)\s*\}\}", callback, content)` is simpler than adding a Jinja2 dependency. Preserving unknown variables is a one-line check in the callback. Used in `sova/commands/templates.py`. [confirmed: 0]
- **Manifest-based file tracking for distributed files**: when deploying files that users may customize, use a JSON manifest (`.sova-manifest.json`) storing content hashes per file. Enables 3-way conflict detection: compare manifest hash (what was installed), current file hash (what user has), new source hash (what source wants). If installed != current AND installed != new, it's a user-modified conflict. Pattern in `sova/commands/manifest.py`. [confirmed: 0]
- **`asyncio.Event` + `wait_for` for interruptible sleep**: instead of `asyncio.sleep(interval)` in poll loops, use `await asyncio.wait_for(stop_event.wait(), timeout=interval)`. Event set = immediate exit; timeout = normal loop continuation. Enables clean shutdown without polling delays. Used in `sova/scheduler/watch.py`. [confirmed: 0]

- **Mock late imports at the source module**: when a function uses `from sova.llm.client import invoke` inside its body (late import), patch at the source: `@patch("sova.llm.client.invoke")`. Patching at the consumer module (`sova.cli.commands.harden.invoke`) does NOT work because the name doesn't exist at module scope. Top-level imports can be patched at either location. This also applies when the consuming module uses multiple deferred imports from different packages -- `@patch("consumer.TriageRole")` fails with `AttributeError` if `TriageRole` is only imported inside a function. This catches all code paths -- direct model construction, bulk inserts, and ORM updates -- unlike service-layer normalization which only covers known entry points. [confirmed: 0]
- **Pre-push hook scope expansion catches pre-existing issues**: when updating a pre-push hook to cover new file paths (e.g., from `dashboard/` to `sova/ tests/`), pre-existing lint/format violations in those files will block the push. Always run the full lint+format cycle (`ruff check --fix && ruff format`) after changing hook scope, and commit the formatting fixes as a separate `style()` commit. [confirmed: 0]
- **Legacy removal with migration bridge**: when removing legacy auto-loading (e.g., `.conf` config fallback), keep the parsing code (key maps, shell config parser) in the same module under a clear section comment (`# -- Legacy config support (used by sova migrate config)`). - **`gh` CLI per-project auth via GH_TOKEN**: `gh auth switch` mutates global state and races in multi-project mode. Instead, use `gh auth token --user <user>` to get the token, then pass `env={"GH_TOKEN": token, ...}` to the subprocess. This is per-subprocess with no global mutation. Implemented in `sova/utils/gh.py:resolve_gh_env()`. The `shell.run()` and `AgentProcess.spawn()` both accept `env` parameter for this. [confirmed: 0]
- **DOM blur handler re-entry on element removal**: when removing an input element from the DOM (e.g., `input.remove()` after saving an inline edit), the `blur` event fires. If the blur handler also calls `input.remove()`, it fails with "The node to be removed is no longer a child of this node." Fix: (1) nullify `input.onblur = null` before calling `input.remove()`, and (2) guard the blur handler with `if (!input.parentNode) return`. Both are needed because blur fires synchronously during remove. Affects all inline-editing patterns in dashboard templates (settings.html, any future editable fields). [confirmed: 0]
- **`pip install .` vs `pip install -e .` in CI integration tests**: use non-editable `pip install .` in CI integration jobs to catch packaging issues (missing `package_data`, broken entry points). Editable installs bypass packaging and can mask these problems. The dev test job still uses `-e ".[dev]"` for pytest access. [confirmed: 0]
- **Post-cutover verification sweep**: after a major rename/removal (e.g., PAK -> SOVA), grep the entire repo for old naming (`pak-agent`, `PAK_ROOT`, old brand strings) to catch survivors. Phase 6 removed ~5,500 lines of bash but missed the old `dashboard/` directory (42 files, 112MB with venv) and stale PAK branding in templates/docs/agent-memory. Cutover PRs should include a grep-based verification step. [confirmed: 0]
- **In-memory SQLite creates separate DB per connection**: `sqlite+aiosqlite://` (no file path) gives each `get_session()` call a new isolated database. Tests that create data in one session cannot verify changes made by a function that opens its own session. Either use a file-backed SQLite (`sqlite+aiosqlite:///tmp/test.db`) or ensure test and production code share the same session factory. [confirmed: 0]
- **Alembic programmatic execution -- pass connection, don't create engine**: calling `alembic.command.upgrade()` inside `conn.run_sync()` fails if `env.py` creates its own async engine (nested event loop). Fix: pass the sync connection via `alembic_cfg.attributes["connection"]` and have `env.py` check for it before creating its own engine. Pattern in `sova/db/session.py:_run_migrations()`. [confirmed: 0]
- **`Base.metadata.create_all` only creates missing tables**: it does NOT add new columns to existing tables. Adding a column to an ORM model silently does nothing to a pre-existing SQLite file -- queries then crash with `OperationalError: no such column`. Always use Alembic migrations for schema changes in production. Keep `create_all` only for test fixtures with in-memory DBs. [confirmed: 0]
- **Default method on ABC removes boilerplate**: when 5+ subclasses have identical `can_skip()` (just `self.name in ctx.completed_steps`), make it the default on `BaseStep` and only override in subclasses with additional logic. Removes ~15 lines of duplication. Pattern: make the ABC method non-abstract with a sensible default, keep `@abstractmethod` only for methods that truly vary. [confirmed: 0]
- **Live dashboard progress needs DB polling**: the dashboard's `AgentState` (in-memory) only knows the outer process state. The inner workflow engine writes `TaskRun.current_step` to the DB as it progresses. To show real-time step progress, `get_all_agents()` must query the DB for each running agent's `current_step` and `total_cost_usd`. This adds ~1 DB query per poll (2s interval) but is the only way to get inner workflow visibility. [confirmed: 1]
- **Tailwind CDN + CSS variables require space-separated RGB channels**: Tailwind's `<alpha-value>` syntax (e.g., `bg-accent/20`) only works when colors are defined as `rgb(var(--x-rgb) / <alpha-value>)` with **space-separated** channel values: `--ctp-blue-rgb: 137 180 250` (NOT comma-separated `137, 180, 250`).
