Orchestration Layer

Everything outside the pipeline steps: task selection, role routing, agent spawning, handoff processing. All deterministic.

0 Orchestration & Routing
WatchLoop.scan() Select next task from backlog by hardcoded priority map (RESEARCHED > TRIAGED > BACKLOG) deterministic
dispatcher Route task to role via _STATE_TO_ROLE dict lookup -- no LLM decisions deterministic
WorkflowEngine Execute steps in fixed order. Skip via can_skip() (config thresholds, not LLM). No reordering. deterministic
auto_handoff Process handoff actions: check auto_execute flag, circuit breaker count, spawn next role deterministic
start_agent() Build prompt from fixed template + CLI command. No LLM prompt generation. deterministic
state transitions GitHub labels via hardcoded _STATE_LABELS map. Board moves via _STATE_TO_BOARD. deterministic
branch naming Fixed pattern: feat/issue-{N} or feat/{sanitized_label} deterministic

Phase 3: Development (Developer Pipeline -- 15 steps)

3 Developer Role
1. sync Pull latest base branch, fetch task data, detect state deterministic
2. assess Verify issue is ready (Gate 3: must be RESEARCHED), check for existing PR deterministic
3. create_worktree Create isolated git worktree, deterministic path + branch name deterministic
4. develop Full Claude CLI: TDD implementation via /develop command. All code decisions. agent
5. simplify Full Claude CLI: code quality pass via /simplify command agent
6. self_review Full Claude CLI: review own changes via /review command agent
7. commit Detect changes, build conventional commit message from context, git add + commit deterministic
8. validate Run pre-push hooks. On failure: LLM reads error output, fixes code (up to 2 retries) llm on failure
9. push git push (force-with-lease if PR exists) deterministic
10. create_pr Title: deterministic from task title. Body: Sonnet LLM call (~$0.01) with structured fallback. llm call
11. wait_external Poll CodeRabbit/SonarCloud status with configurable timeout. Pure polling loop. deterministic
12. address_findings If external findings exist: LLM reads SonarCloud + CodeRabbit issues, fixes code llm if findings
13. monitor_ci Poll CI checks. On failure: LLM reads failure logs, fixes code (up to 3 retries) llm on failure
14. extract_memory Haiku call (~$0.01): extract reusable learnings from run context llm call
15. handoff_reviewer Write structured handoff JSON with auto_execute=true for reviewer deterministic

3. commit Build "fix: address review findings" message, git add + commit deterministic
4. validate Run pre-push hooks. On failure: LLM fixes violations (up to 2 retries) llm on failure
5. push git push --force-with-lease (post-rebase history rewrite) deterministic
6. monitor_ci Poll CI. On failure: LLM reads logs, fixes code (up to 3 retries) llm on failure
7. resolve_reviews Dismiss bot CHANGES_REQUESTED, resolve CodeRabbit threads via GitHub API deterministic
8. extract_memory Haiku call: extract learnings from address-review context llm call

Determinism Opportunities

Actions currently using an LLM that could be replaced with deterministic code.

Current Action Current Mode Proposed Mode How
PR title generation llm --> code Strip existing prefix from task title, re-wrap with type(#N). DONE
PR body generation code --> code Deterministic template via _build_pr_body(): commits + diff stats + issue body excerpt (500 char limit). Done.
Commit message (step 7) code code Already deterministic. Verify no agent override path exists.
Memory extraction llm --> code Rule-based: extract file paths, error patterns, test failures. Low value vs cost -- consider removing entirely or running only on failure.
Review feedback ingestion llm --> code Parse review comments structurally (category, severity already in JSON). Store raw findings, no summarization needed.
Triage assessment agent --> llm call Replace full agent with single structured LLM call (Haiku): input=issue body, output=JSON {priority, area, complexity, labels}. No tool access needed.

Must Remain Non-Deterministic

Core value -- agents exist for these:
  • develop (step 4) -- TDD implementation is the product's core value proposition
  • simplify (step 5) -- requires understanding code semantics to identify improvements
  • self_review (step 6) -- needs to reason about correctness, security, design
  • address_review (AR step 2) -- must understand reviewer intent and fix accordingly
  • research (phase 2) -- exploratory codebase navigation, can't be templated
  • spec (phase 2) -- synthesis of research into structured specification
  • reviewer (phase 4) -- structured LLM call already (Sonnet + JSON schema), not a full agent

Acceptable LLM usage -- conditional, bounded:
  • validate fix (step 8) -- only fires on hook failure, bounded to 2 retries
  • CI fix loop (step 13) -- only fires on CI failure, bounded to 3 retries + budget check
  • rebase conflicts (AR step 1) -- only fires on conflict, bounded to 3 attempts
  • address_findings (step 12) -- only fires when external tools report issues

Design principle: agents do the creative work (develop, review, fix). Everything else -- routing, state management, git operations, PR metadata, handoffs, CI polling, external review thread lifecycle -- is deterministic code. When adding new pipeline features, default to code. Only reach for an LLM when the task requires understanding natural language or generating novel code.

Key takeaway: The orchestration layer is 100% deterministic -- no model dependency in routing, scheduling, state management, or handoff processing. Non-determinism is concentrated in 6 agent sessions (the creative work) and 9 targeted LLM calls (5 of which are conditional -- only fire on failure). With the proposed opportunities above, the strict determinism ratio could reach ~65% and the effective ratio ~82%.
